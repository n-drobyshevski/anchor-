# Anchor web: multi-screen dashboard plan

## Context

The web chat (`app/web/`) works: vanilla JS in one 760-line `app.js`, a strict CSP with Trusted Types, SSE, and passphrase plus a Telegram code for login. The next step adds several screens with control panels: memory, state, check-in and journal, proposals, and research.

Hand-written DOM code won't hold up at that size. We'll move to a small framework **before** adding panels, without giving up the security model:

- no Node in the pipeline
- the same CSP, no weaker
- one set of business rules shared by Telegram and the web

## 1. Frontend stack: Preact, htm and Signals, with no build step

| Package | Version | Why |
|---|---|---|
| `preact` (+ `preact/hooks`) | 10.29.8 | ~4 KB; React-style components |
| `htm` | 3.1.1 | JSX-like `` html`...` `` syntax with no compiler and no `eval` |
| `@preact/signals` (+ `signals-core`) | 2.11.2 / 1.14.4 | shared state between screens (session, connection, counters) |

**Vendoring, not a CDN.** `scripts/vendor_web.py`:
- downloads the npm tarballs at pinned versions and checks the `sha512` integrity from the registry
- copies only the ES module files into `app/web/static/vendor/`
- rewrites bare imports (`from "preact"`) into relative ones (`./preact.module.js`), because an import map is an inline script and CSP forbids those
- writes `vendor/VENDOR.lock` with the version and sha256 of every file

Updating a dependency means running the script by hand. No automatic updates.

**Security contract (the tests enforce it):**
- `test_web_vendor.py` checks that the vendored files match `VENDOR.lock`, catching any silent edit. It also checks they contain no `eval(` or `new Function`.
- `test_web_static.py` now scans all of our code under `static/app/**`, not only `app.js`. The existing forbidden-API list stays. New additions:
  - `dangerouslySetInnerHTML`
  - `style=` string attributes in templates; use classes, or style objects if unavoidable
  - `href=` built from data unless it goes through `safeUrl()`, which allows only `https:` and returns `#` otherwise
- CSP is unchanged: `script-src 'self'`, `require-trusted-types-for 'script'`. Preact escapes text by default. Its only `innerHTML` path is `dangerouslySetInnerHTML`, which is banned in our code and throws under Trusted Types anyway.

**Static file serving.** The current whitelist of 4 routes is replaced by a manifest built once at startup:
- walk `static/` and allow only the extensions `.js .css .svg .html .woff2`
- look up files by exact string match against the manifest; no path from the request ever reaches the filesystem, so traversal is impossible
- serve with the content-type for the extension, `ETag`, and `Cache-Control: no-cache`

## 2. Frontend structure

```
app/web/static/
  index.html            # empty <div id="root">, one <script type=module src=/static/app/main.js>
  app.css               # tokens (light/dark) + components; stays one file
  vendor/               # generated by vendor_web.py, not edited by hand
  app/
    main.js             # mount, init session
    html.js             # htm.bind(h) + safeUrl()
    api.js              # fetch wrapper: JSON, 401 → login, 429 → retry_after, client_key
    store.js            # signals: auth, conn, route, badges (proposals, cards)
    sse.js              # EventSource + backoff, dispatches message/edit/typing/toast/invalidate
    router.js           # hash router: #/chat #/state #/memory #/checkin #/proposals #/research
    ui/                 # Shell, Nav, Login, Toast, Confirm, Empty, Spinner
    screens/            # Chat, State, Memory, Checkin, Proposals, Research
```

**Layout:**
- On mobile, a bottom tab bar with 5 items: Chat · State · Memory · Check-in · More. "More" holds proposals and research.
- On desktop (≥ 900px), a left sidebar with the content capped at 42rem.
- Chat stays the default screen.
- Badges show the number of pending proposals and pending cards.

**Hash router.** No server-side routes are needed. Everything stays on `/`, and a reload keeps the screen.

**Live updates for panels.** The hub gets a new SSE event, `invalidate {topic}`, with topics `state`, `memory`, `proposals`, `checkin`, `cards`. An open panel refetches its data when its topic arrives. Sources:
1. Web mutations publish it themselves after a successful write.
2. The tail (`app/web/tail.py`) also follows `state_change`, the audit table every `update_state`, forget and adopt writes to. It maps each row to a topic, so changes made from Telegram show up in the web too.
3. As a fallback, a panel refetches on `visibilitychange` and on navigation.

## 3. Backend: one set of rules for both transports

**Split `routes.py`**, which is already 635 lines:
- `app/web/http.py`: `json_response`, `read_body`, `require_session`, `rate_limited`. These are moved out of `routes.py` without changes.
- `app/web/routes.py`: static files, auth, chat. Unchanged in behavior.
- `app/web/panels/{state,memory,checkin,proposals,research}.py`: each provides `register(app)`.

**Moving business logic out of the tg handlers into core.** This is the key part, so the web doesn't fork the rules. New functions go in `app/core/commands.py`, and `app/tg/router.py` is switched to call them:

| Function | What it does, as in Telegram today |
|---|---|
| `set_due(session, clock, text, source)` | `update_state` `due_action` + `due_set_at`, expire the pending proposal for that field |
| `set_focus(session, clock, enabled, source)` | the same for `focus_on`/`focus_since` |
| `set_quiet(session, clock, until\|None, source)` | `quiet_until`, plus `cancel_outbound` when set |
| `set_timezone(session, tz, source)` | `ZoneInfo` validation + `update_state` |
| `expire_proposal_for(session, clock, field) -> Proposal\|None` | the core half of `_expire_proposal_for`; the tg or web layer then retires the Telegram buttons itself |

**Rules for every mutating panel endpoint:**
- First run `require_session`, then the CSRF middleware (it already covers all `/api/*`), `read_body` with validation, and the `limiter.check_panel_write()` rate limit. The limit is a new shared bucket of 60 per minute.
- Call `checkin.clear_awaiting(session)`, as any Telegram command does through the middleware.
- Write only through core functions: `update_state`, `write_memory`, `hard_delete` + `record_change`, `proposal.accept/reject`, `cards.adopt/reject`, `enqueue_study/read`. Never write SQL against the tables directly.
- Use a new audit source, `"web"`, in the `Source` literal. If `state_change.source` has a CHECK constraint, it gets a migration.
- If the change makes a live Telegram keyboard stale (a proposal, a check-in), retire its buttons through the real bot, the way `_expire_proposal_for` does.
- Log only the `event` name plus `route`. Never log memory text, notes or card content.

## 4. Screens

### W2 State
- **Read endpoint:** `GET /api/state`, structured JSON, not reused Russian text:
  - `focus_on`/`since`, `due_action`/`set_at`, `streak`, `last_checkin_at`, `quiet_until`, `timezone`
  - `persona_active`, `ignored_in_row`, `next_planned_for`
  - spend today (total and by category), plus the cap
  - memory count, and safety_event counts (welfare, distill, search) as numbers only
  - Not exposed: `chat_id`, `awaiting`/`awaiting_ref`, and raw `state_change` rows.
- **Write endpoints:** `POST /api/state/{due,focus,quiet,timezone}` through `commands.*`. Separately, the pause toggle `POST /api/state/pause {"on": bool}` sends `/out` or `/in` as a synthetic web update, so all pause logic stays in the turn pipeline.
- **UI:**
  - cards for focus, action, streak, "quiet until" and time zone
  - a spend progress bar against the cap
  - inline editing of fields
  - the time zone chosen from a list via `Intl.supportedValuesOf('timeZone')`

### W2 Proposals (small; comes with State)
- **Read:** `GET /api/proposals` returns the pending proposal plus the last 20 decided ones.
- **Write:** `POST /api/proposals/{id}/accept|reject` calls `proposal.accept/reject`, which already writes with `source="button"` and is idempotent. After that, retire the Telegram buttons.
- **UI:** a proposal card that shows the "why" (`reason`), with "Принять" and "Отклонить" buttons. This closes the current gap where these buttons are only in Telegram.

### W3 Memory
- **Read:** `GET /api/memories?offset&limit&kind&pinned` via `list_active`. A `source` label marks whether the user or the model added each memory (`extractor`, `adopt`).
- **Writes:**
  - `POST /api/memories {kind, text}` uses `write_memory` directly with the kind picked in the form. The two-step `PendingMemory` flow isn't needed here. Text is capped at `MEMORY_TEXT_MAX`, duplicates are rejected via `near_duplicate`, and the response distinguishes created, duplicate and superseded.
  - `POST /api/memories/{id}/pin|unpin` goes through `run_set_pinned` logic moved into core, including the `MEMORY_PINNED_MAX` cap.
  - `DELETE`-style `POST /api/memories/{id}/forget` calls `hard_delete` + `record_change`, with a content-free audit row. The UI asks for confirmation first.
- **UI:** a list grouped by kind, filters, a search field that filters on the client within the loaded list, pin as a toggle, and forget through a confirmation dialog.

### W4 Check-in + Journal
- **Check-in** (one form: rating 1–5, due action result, note up to 500 characters):
  - `POST /api/checkin` validates, then goes through `checkin.start` → `set_rating` → `set_due_result` → `set_awaiting_note`.
  - Then it **enqueues a synthetic web update**: the note text, or the callback `c:n:skip` if there is no note. From there the existing path runs: `finish_and_react` → `turn.run(CHECKIN_FLAG)` inside the single worker, including the guard against a double LLM call and the pause-word check. No new LLM path is added. Anchor's reaction arrives in the chat over SSE.
  - The daily state machine and the "redo on the same day" behavior come from core.
- **Journal:**
  - Add a new core function `list_journal(session, offset, limit)`; tick's private helper is left alone.
  - `GET /api/journal` is read-only.
  - The UI shows a feed by day, next to the history of check-ins with ratings and a small 30-day rating chart. The chart is plain inline SVG with no library.
  - `GET /api/checkins?days=30`.

### W5 Research
- Every endpoint first checks `settings.RESEARCH_ENABLED` and returns 404 when research is off, the same way Telegram behaves.
- **Reads:**
  - `GET /api/research/jobs` returns status, `error_code` and cost.
  - `GET /api/research/cards?page` uses `pending_page`. `GET /api/research/cards/{id}` uses `get_card`.
  - Hidden and high-risk cards are **never** returned. `GONE` and `FORBIDDEN` both become the same 404, so the API doesn't reveal whether a hidden card exists.
  - `StudyClip.text` (raw page content) is not exposed.
- **Writes:**
  - `POST /api/research/study {packet, topic, client_key}` and `POST /api/research/read {url, client_key}`. Deduplication uses an in-memory `client_key → job_id` map for 10 minutes, because `enqueue_*` isn't idempotent itself. Quotas and caps are enforced inside `enqueue_*`, and the refusal codes are translated into Russian messages.
  - `POST /api/research/cards/{id}/adopt|reject` uses `cards.adopt/reject`, keeping the one-way safety boundary of `cards.py`.
- **UI:**
  - a list of jobs with statuses and a list of cards (the list shows only the domain; the detail view shows the full URL through `safeUrl`, with `rel="noopener noreferrer"`)
  - "Принять в технику" / "Отклонить" buttons
  - a start-research form

## 5. Milestones (one PR each)

| # | Contents | Result |
|---|---|---|
| **W1 Foundation** | `vendor_web.py` + vendor + lock; static-file manifest; `http.py` split; shell, router, nav, login, toasts; **1:1 port of the chat** to Preact; the `invalidate` event plus a `state_change` tail; test updates | same features, new architecture, E2E green |
| **W2 State + Proposals** | `app/core/commands.py` + router moved onto it; `"web"` source; state and proposals panels; badges | control of state and proposals from the web |
| **W3 Memory** | pin logic moved to core; memory panel | full memory management |
| **W4 Check-in + Journal** | `list_journal`; check-in form through a synthetic update; check-in history + SVG chart | daily ritual in the web |
| **W5 Research** | research panel with `client_key` dedup | research from the web |

W1 adds no features: it's a pure port. That makes it easy to check parity with the current chat.

## 6. Testing (each milestone)

- **pytest per panel** (`tests/test_web_panel_*.py`):
  - 401 without a session, 403 on a foreign Origin, 429 when rate-limited
  - validation, and a check that each endpoint goes through core (the same audit row, the same `source`)
  - the side effects: proposal expiry, `clear_awaiting`, `cancel_outbound`, `invalidate`
  - no hidden cards leak, and none of: memory text in logs, `chat_id`, raw clip text
- **Parity tests for the core extraction.** The Telegram commands `/due /focus /quiet /tz` give exactly the same result before and after `commands.py`. The existing router tests must pass unchanged.
- **`test_web_vendor.py`** and the extended **`test_web_static.py`**, described in §1.
- **E2E (Playwright + the preinstalled Chromium).** Move the harness from the scratchpad into `scripts/web_e2e.py`; it runs by hand with `uv run --with playwright`, so there is no new dev dependency. Scenario:
  - login, then chat (send and receive)
  - move through every screen
  - one action per panel
  - zero console errors, zero CSP violations
  - screenshots at 390×844 dark and 1280×800 light
- Migrations, if any, go through `upgrade → downgrade → upgrade`.

## 7. Decisions

- Order: W1 → State + Proposals → Memory → Check-in + Journal → Research.
- Mobile navigation: the bottom tab bar.
- Changes made through a panel are **silent in Telegram**. They go only into the `state_change` audit and to the web through `invalidate`. The bot writes nothing to Telegram about them.

## 8. Out of scope

- `/delete` and `/export` stay Telegram-only (decision from the web-chat plan).
- Streaming LLM tokens (the provider isn't streaming).
- PWA and offline mode. A manifest can be added later with no effect on CSP.
- Multiple users or roles.
